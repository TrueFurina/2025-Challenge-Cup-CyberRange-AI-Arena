## 三、P1 级问题（影响功能/测试/可维护性）

### P1-1：零自动化测试 + CI 配置与事实不符（最高优先级）
- **位置**：`submission/代码/`（无 test 文件）、`.github/workflows/ci-cd.yml` 第 45 行
- **问题**：CI 配置 `pytest --cov=backend`，但项目 **0 个测试文件**——CI 的 lint-and-test job 必然失败，black/isort 也会因格式不符失败
- **影响**：CI 流水线形同虚设；评委若按 CI 检查会立刻发现测试缺失；答辩"测试通过"声明无法自证
- **建议**：
  1. 补最小测试集：`test_auth.py`（注册/登录/鉴权）、`test_arena.py`（对抗回合/态势感知）、`test_eval.py`（评估分析器/混淆矩阵）、`test_security.py`（提权/越权回归）
  2. 修 ci-cd.yml：black/isort 校验要么运行格式化要么去掉；`--cov=backend` 需有 tests/ 目录
  3. 至少保证 CI 绿：`pytest` 通过后再提"全量验证"

### P1-2：AI 路由全部公开（session_id 任意访问）
- **位置**：`backend/ai_routes.py` 全部 7 个路由（scenario/session/round/run/analyze/report）
- **问题**：无任何鉴权，任何人可创建会话、跑对抗、读 session 决策流、导出报告
- **影响**：演示级可接受，但"任意 session_id 越权读取"在答辩时可能被追问；与"轻量 token 鉴权"的安全声明不自洽
- **建议**：AI 路由加 `_current_user_id()` 可选鉴权（已登录才可用），或文档明确"AI 演示路由公开供评委体验"

### P1-3：无 CSRF 防护
- **位置**：`app.py` / `backend/`（无 CSRFProtect）
- **问题**：基于 Cookie 的会话若上线，CSRF 可伪造请求
- **影响**：当前 token 内存机制缓解了部分风险，但 `admin` 的 POST 操作（改密码/删用户）无 CSRF token
- **建议**：演示项目可接受；若答辩强调安全，加 Flask-WTF CSRFProtect（5 分钟工作量）

### P1-4：AI 调用无重试机制
- **位置**：`ai_agents/client.py` `_post_chat()`（timeout=30，无重试）
- **问题**：LLM 单次失败直接 fail-open 回退规则引擎；网络抖动时攻击/防御 Agent 全走规则兜底，对抗结果失真
- **影响**：答辩演示时 LLM 偶发失败会显得"AI 能力弱"
- **建议**：加 1 次重试（指数退避 1s）+ 超时从 30s 提到 60s；重试仍失败再 fail-open

### P1-5：evaluation_analyzer 部分"简化实现"返回固定值
- **位置**：`ai_agents/evaluation_analyzer.py` 的 `_assess_collaboration_effectiveness`（固定 75）、`_analyze_skill_distribution`（固定值）
- **问题**：从早期版迁移时保留了简化占位实现，答辩时若评委深挖会显得"评估是拍脑袋"
- **影响**：与"深度评估"宣称不符
- **建议**：把协作效果/技能分布改为基于真实对抗数据计算（攻击得手率/防御动作数/技术多样性）

## 六、锐评（不客气的实话）

### 做得好的
1. **安全修复是真功夫**：9 个漏洞全部动态验证，不是纸面声明；鉴权、CORS、debug 这些 P0 项都处理到位，这在学生作品里属于上游水准
2. **架构演进脉络清晰**：从早期 programs 版 → 最终版 → 迁移评估分析器/态势感知，代码是"长出来"的不是"拼出来"的，模块分层（routes/ai_agents/memory/ledger）干净
3. **fail-open 哲学贯彻到底**：LLM 挂了规则兜底，记忆写失败不阻断，态势更新失败不影响对抗——这个工程意识很多研究生作品都没有
4. **迁移动作专业**：从被删的 programs 里把独有能力（评估分析器 491 行、态势感知）抢救迁移，还先备份到 D:/Archive/，有版本管理素养

### 说得直的
1. **"零测试"是致命伤**：一个 3341 行的安全类项目，0 个自动化测试，CI 还配置了 pytest 但必然失败——这在国赛答辩是"送命题"。评委问"你们怎么保证代码质量"，你只能说"手动测过"，而竞品（2023 作品表里 57 件 LLM+Agent 项目）至少有几行 pytest。**这是必须补的，没有商量**
2. **"评估分析器"有水分**：技能画像、协作效果部分是迁移时的简化占位（固定 75 分），宣称"深度评估"但深度有限。要么把计算做实，要么别标榜"深度"
3. **AI 路由"裸奔"与安全声明不自洽**：你花大力气做了 token 鉴权，却把 AI 演示路由全公开——答辩时如果安全评委问"那 session 越权呢"，你只能解释"演示需要"，这是自己给自己挖坑
4. **文档 > 代码的倒挂**：10 篇文档、README、PRD、白皮书、简历全齐（文档是 2026 项目级别的完整度），但测试 0 行。评委一眼能看出"包装比内核厚"

### 一句话总结
> **这是一个"工程意识好、安全底子硬、但测试为零、评估有水分"的作品。** 补 4 个测试文件（一天工作量）+ 做实评估计算（半天）+ 修 CI（一小时），就能从 B+ 冲到 A-。测试短板不补，前面的安全功夫都会在答辩时被"怎么保证质量"一个问题击穿。
